# ADR-0002：会话权限快照不可变，权限变更只影响后续调用

- 状态：已接受
- 日期：2026-10-25
- 相关安全不变量：**不变量 3**（进行中的操作不受权限变更影响）

## 背景

LLM 会话的权限可能在会话进行中被管理员调整（收窄可见 VM、降低配额、
移除 power 权限）。如果权限校验在每次操作时实时读取"当前权限"，会出现
两类问题：

1. **TOCTOU**：一个已经通过校验、正在执行的 `vm_start` 可能因为中途权限
   收紧而处于"半授权"状态——它消耗的配额、启动的进程归属变得不明确；
2. **不可重放**：审计无法回答"这次调用当时是基于哪份权限被允许的"。

## 决策

1. `SessionPerms` 是**不可变值对象**（pydantic，深拷贝后修改生成新实例）；
2. 每次 tool 调用**开始时**通过 `SessionGuard.snapshot()` 取一份**深拷贝**
   并持有到操作结束；整个权限判断、配额检查、审批绑定都用这份快照；
3. `update_perms()` 生成新快照并把 `perms_generation + 1`；审批记录
   `session_generation`，审批决定只对创建它的那一代权限负责；
4. 可见列表收窄时同步裁剪权限矩阵中的"孤儿"授权，避免残留；
5. 会话过期 / 停用后 `snapshot()` 直接抛 `PermissionDeniedError`。

## 后果

- 审计条目可精确定位"当时生效的权限代次"（`session_generation`）；
- 中途收紧权限**不会**让进行中的长操作（等待审批、等待 QMP）突然失败，
  语义清晰、可预期；
- 代价：内存中同时存在多代快照（每次修改都深拷贝），规模极小（权限矩阵
  通常 < 64 条），可忽略。
